# components_v1 실제 GPU 서버 확인

확인 시각: 2026-10-17 00:47 KST. 코드 보강 전에 현재 상태를 확인했다.

이 문서는 당시 상태를 보존한다. 이후 01:08 KST에 서버 배치·입력 검사 보강·5,000토큰 실제 생성·저장·재개 확인까지 완료했다. 현재 상태는 [5,000토큰 준비 결과](extended_v1_ready.md)를 따른다.

## 결과와 범위

**실제 RTX 4090에서 모델 로딩·양자화·개발 이미지 추론 22조건을 모두 통과했다. 전처리 130개 입력의 CPU float32·GPU bf16 최대 차이는 모두 0이었다.** 로컬 테스트는 실행하지 않았다.

새 `runtime.py`와 `case_config.py`는 서버에 아직 배치되지 않았다. 현재 작업 트리의 두 파일을 SSH 표준입력으로 전달해 서버 Python 메모리에서 직접 실행했다. 가짜 모델이나 대체 양자화 구현을 사용하지 않았고, 서버의 기존 실행 파일·공격 PNG·측정 CSV를 덮어쓰지 않았다. 공통 모듈은 서버에 있는 실제 `settings.py`, `quant_rtn.py`를 import했다.

이번 확인은 실제 모델 기능 확인이다. 새 실행 도우미의 배치·tmux 시작·중단 후 재개·최종 CSV 저장을 포함하는 전체 파이프라인 검증이나 본측정 완료를 뜻하지 않는다. 본 실험은 시작하지 않았다.

## 실제 입력과 공통 파일

- 서버 `README.md`, `공통/settings.py`, `공통/quant_rtn.py`, `공통/image_list.csv`의 Git blob 해시가 정적 검토에서 읽은 GitHub main의 해당 파일과 모두 같았다.
- 공통 공격 세트와 확장 공격 세트 각각 eval 30장의 실제 PNG를 읽었다. clean/noise/adv SHA256, PNG RGB·448×448, selection의 이미지 ID·기록된 L∞를 대조했다.
- 지정 식 `np.random.default_rng([2026, coco_id])`로 픽셀별 ±8 노이즈를 다시 계산했다. 서버 noise PNG와 모두 정확히 같았다.
- 각 공격 PNG와 clean의 실제 픽셀 차이를 다시 계산했다. 두 세트 모두 최대 L∞=8이고 위반은 없었다. selection에 기록된 L∞와도 모두 같았다.
- 전처리는 dev clean/noise 10개, eval clean/noise 60개, 두 세트의 adv 60개, 총 130개를 확인했다. 직접 구성한 입력과 processor의 차이는 CPU float32와 GPU bf16 모두 정확히 0이었다.

## 실제 모델 확인

| 대상 | 실행한 양자화 | 통과 | 양자화된 Linear |
|---|---|---:|---:|
| bf16 원본 | ref | 1/1 | 0 |
| 연결부 C | RTN8·6·5·4·3, bnb8·4 | 7/7 | C의 2개 |
| 언어모델 L | RTN8·6·5·4·3, bnb8·4 | 7/7 | L의 196개 |
| V+C+L | RTN8·6·5·4·3, bnb8·4 | 7/7 | V 128 + C 2 + L 196 = 326개 |

모든 조건에서 실제 모델을 새로 로딩하고 개발 이미지 `000000000632`의 clean 입력으로 생성했다. eval 응답을 생성하거나 조건을 조정하지 않았다. 기능 확인에서는 공통 ref를 한 번 확인해 총 22조건이며, 정식 실험 계획은 C/L/VCL 각각 ref를 포함한 8조건 그대로다.

모든 조건에서 예상 census와 비대상 부품의 미변환을 확인했다. 출력층 H는 양자화되지 않았고, 입력 임베딩·출력층은 bf16과 동일 저장소 공유를 유지했다. RTN 전후에는 보호된 Parameter의 정체성·저장 위치·버전·dtype도 같았다. 실제 생성 토큰으로 EOS·토큰 수·상한 도달 판정을 대조했다.

RTN의 모델 footprint는 원본과 같은 4,417,971,872 bytes였다. RTN은 bf16에 저장하는 모의 양자화이므로 실제 저장 공간 축소 실험으로 해석하지 않는다. bnb는 실제 packed weight를 로딩했다. bnb8에서 관찰된 bf16 입력의 float16 변환 메시지는 backend의 동작이며 실행 실패는 없었다.

## 남은 사항

1. 새 C/L/VCL 실행 파일의 서버 배치와 전체 파이프라인 확인은 아직 하지 않았다.
2. 정적 검토에서 발견한 자동 입력 검사의 빈틈 두 가지는 수정하지 않았다. 이번 서버의 실제 noise/adv는 규칙에 맞았지만, 새 실행 경로가 항상 노이즈를 재구성하고 PNG의 실제 L∞를 재검사하도록 보강하는 일은 별도다.
3. 공통 규칙의 유효 이미지·ref 성공 분모를 적용하는 ASR/전이율 분석은 아직 구현되지 않았다. 이번 결과는 그 분석의 검증이 아니다.
4. PR·공유 전 개인 절대 경로가 담긴 과거 로컬 검사 기록 정리도 남아 있다.

검증용 코드 수정, 본측정 시작, GitHub commit/push/PR 생성은 하지 않았다. 이 문서는 서버에서 관찰한 결과를 기록한 것이다.
