# Qwen2-VL 시각 인코더 양자화 — 공통 설정 v1 (r01)

[B팀 안내로 돌아가기](../../README.md)

## 1. 실험 목적과 변경점

프로젝트 공동 설정을 바탕으로, 시각 인코더만 양자화했을 때 동일한 공격 이미지의 출력 길이가 어떻게 달라지는지 측정했다.

원본 bf16 모델에서 만든 공격 PNG를 고정하고, 같은 사진의 원본(clean)·무작위 노이즈(noise)·공격(adv) 입력을 원본과 시각 인코더 양자화 모델에서 비교했다. **성공·실패, ASR, 전이율은 아직 평가하지 않았다.**

**공동 예시 코드와 구현 차이가 있다.** 공동 설정 v1·이미지 목록·V 전용 양자화 조건·CSV 형식은 따르지만, 예시 코드의 “500토큰 이상이면 중단·마지막 상태 저장” 대신 “EOS 없는 정확한 512토큰을 연속 두 번 확인하면 중단·최선 후보 저장”을 사용했다. 따라서 예시 구현과 완전히 같은 실험으로 해석하면 안 된다. [실행 당시 프로토콜](../../results/qwen2vl_vision_common_v1_r01/PROTOCOL.md)에 원래 계획을 보존했다.

## 2. 설정과 이미지 채택 규칙

| 항목 | 적용한 값·규칙 |
|---|---|
| 실험 ID | `qwen2vl_vision_common_v1_r01` |
| 이미지 세트 ID | `qwen2vl_attack_common_v1_i300_cap512_s01` |
| 원본 모델 | `Qwen/Qwen2-VL-2B-Instruct`, bf16 |
| 측정 대상 | 시각 인코더(V)의 Linear weight만 양자화 |
| 모델 조건 | `ref`, `rtn-V-8`, `rtn-V-6`, `rtn-V-5`, `rtn-V-4`, `rtn-V-3`, `bnb-V-8`, `bnb-V-4` |
| 사진·입력 | COCO val2017 eval 30장 × clean·noise·adv. dev 5장은 점검용 |
| 전처리 | RGB 448×448 직접 BICUBIC 리사이즈, 무손실 PNG |
| 노이즈 대조군 | seed `[2026, image_id]`, 각 채널에 ±8을 더한 뒤 0…255로 제한 |
| 공격 변화 제한·갱신 크기 | 채널당 최대 8, 즉 `8/255`; 한 번의 갱신 크기 `1/255` |
| 기타 공격 설정 | target 128, refresh 20, `w_unc=0.05`, `w_div=0` |
| 질문·생성 | `Describe this image in one sentence.`, greedy |
| 최대 출력 | 512토큰 |
| 공격 갱신 예산 | 최대 300회 |
| 후보 출력 확인 | 갱신 1, 21, …, 281회 및 마지막 300회. 조기 종료 시 이후 확인은 생략 |
| 조기 종료 | EOS 없이 정확히 512토큰을 낸 확인이 두 번 연속이면 종료 |
| 채택 | 관찰한 후보 중 `(출력 상한 도달 여부, 토큰 수)`가 가장 큰 후보. 동률이면 먼저 관찰한 후보 |
| 저장 확인 | 최종 PNG를 다시 읽어 채택 후보의 토큰 수·상한 도달 여부와 일치하는지 검사 |
| CSV 형식 | 공동 지침의 8열, 한 응답당 한 행 |
| 평가 행 수 | 30장 × 8모델 조건 × 3입력 = 720행 |

대표 CSV는 `model,case,image_id,input,n_tokens,hit_cap,latency_s,text` 순서다. `hit_cap`은 EOS 없이 512토큰 상한에 도달했는지를 뜻한다.

[공격 생성 기록](../../results/qwen2vl_vision_common_v1_r01/attack-records.jsonl)은 사진별 원본·저장 PNG의 응답과 생성 검증 기록 30개를 한 줄씩 모은 파일이다. 모든 평가 응답의 토큰 ID를 별도로 수집한 기록은 아니다.

채택 PNG와 사진별 정보는 [이미지 세트](../../adv/qwen2vl_attack_common_v1_i300_cap512_s01/)의 `selection.json`·`SHA256SUMS`에 있다. 모든 모델 조건에 같은 PNG를 사용했다. 최종 PNG의 최대 픽셀 변화와 공격 경로·평가 프로세서의 전처리 일치 여부를 검사했다.

토큰 수는 생성된 EOS가 있으면 그 토큰도 포함한다. Qwen EOS ID `151645`, `151643`을 모두 확인했다. 토큰 수가 상한과 같아도 마지막에 EOS가 있으면 출력 제한 도달로 세지 않는다.

`latency_s`는 CUDA 동기화를 포함한 생성 호출 시간이다. 모델 로딩과 공격 이미지 최적화 시간은 제외한다. RTN은 group 64의 양자화 값을 부동소수점 가중치로 되돌려 쓰는 모의 양자화이며, bnb는 실제 8비트·4비트 모듈을 사용한다. 4비트 형식은 NF4다.

아래 표는 출력 길이·생성 시간의 기술 통계다. 출력 상한 도달 장수를 공격 성공 수로 단정하거나, 이 표만으로 답변 정확도·메모리 절감·토큰당 속도의 우열을 판단하지 않는다.
