# 두 팀이 맞춰야 하는 것

이 문서가 두 팀 사이의 약속 전부다. **여기 없는 것은 팀이 알아서 정한다.** 나머지 파일(실험설계·진행단계·결과형식·일정)은 배경 설명과 참고다.

## 목표

원본 모델로 만든 공격 사진이, **비전 인코더를 n비트로 양자화한 모델**에서 몇 % 살아남는지를 두 모델(SmolVLM-256M, Qwen2-VL-2B)에서 같은 방법으로 잰다. 함께 정상 답이 얼마나 달라지는지도 잰다.

10/30 발표의 핵심 그림 하나: **가로축 비트 수(16·8·6·5·4·3), 세로축 전이율, 선 두 개(두 모델).** 이 그림이 나오게 하는 것이 두 팀의 공통 목표다.

## 실험 순서

| | 무엇을 | 언제 |
|---|---|---|
| **1차** | **양자화하는 부품은 비전 인코더로 고정하고, 비트만 8·6·5·4·3으로 바꿔** 전이되는지 본다 (`settings.PRESETS["phase1"]`) | 10/30 발표까지. 두 팀 모두 |
| 2차 | 시간이 남거나 1차에서 더 볼 것이 생기면, **부품을 바꿔 가며**(연결부·언어모델·출력층·전체) 비트별로 본다 (`PRESETS["phase2"]`). 공격 사진은 1차 것을 그대로 쓴다 | 11월 |

비전 인코더로 고정한 이유는 예비 실험에서 결과가 갈린 유일한 부품이기 때문이다(`실험설계.md`).

## 반드시 같은 것

값은 `settings.py`에 있다. 코드에서 import해서 쓰면 틀릴 일이 없다.

| 무엇 | 값 |
|---|---|
| 질문 | "Describe this image in one sentence." |
| 답 생성 | greedy, 상한 512 토큰 (`settings.GEN_KWARGS`를 그대로 넘긴다) |
| 종료 토큰 | 모델 generation_config의 eos 목록 전부 (Qwen은 2개) |
| 노이즈 상한 | 8/255 |
| 사진 | `image_list.csv`의 eval 후보 중 확정된 30장(`eval_v1.txt`). 모델 입력 크기 정사각형(SmolVLM 512, Qwen 448)으로 리사이즈, PNG 저장 |
| 입력 3종 | 원본(clean) / 무작위 노이즈(noise: 픽셀마다 ±8, 시드 `[2026, COCO id]`) / 공격(adv) |
| 기준 모델 | bf16 원본 = 경우 `ref` |
| 양자화 | 비전 인코더의 Linear weight만. 비트 8·6·5·4·3은 `quant_rtn.apply_rtn`, 더해서 bitsandbytes 8·4 (`settings.PRESETS["phase1"]`) |
| 경우 이름 | `ref`, `rtn-V-4`, `bnb-V-8` 형식 |

## 반드시 내야 하는 것

| 산출물 | 어디에 | 형식 |
|---|---|---|
| 공격 사진 30장 | `<팀>/data/adv/<COCO id 12자리>.png` | PNG + `attack_log.csv` + `SHA256SUMS` (열은 `결과형식.md` 3절) |
| 실험 결과 | `<팀>/results/<실행ID>.csv` + `.json` | 열은 `결과형식.md` 1절. 답 하나가 한 줄, `ref` 포함 |
| 실행 기록 | 실험기록 이슈 (템플릿) | 실행마다 하나 |

결과 CSV의 열 이름만 맞으면 분석은 공동 담당 한 명이 한 코드로 돌린다. 팀이 지표를 직접 계산할 필요는 없다.

## 상한

공격 반복 500회, 사진 한 장 SmolVLM 5분 / Qwen 20분, 1차 전체 GPU 10시간. 넘길 것 같으면 사진 수가 아니라 경우 수를 줄인다.

## 하지 말 것

- 평가용 30장으로 공격 설정을 조정하는 것 (조정은 dev 5장으로)
- 공격 사진을 고정(해시)한 뒤 다시 만드는 것
- 결과 CSV를 손으로 고치는 것
- JPEG 저장, 질문 변경, 샘플링 켜기
- 공격 사진을 팀 밖으로 보내는 것

## 그 외는 자율

코드 형태(노트북이든 스크립트든), 실행 순서, 어느 기계에서 돌릴지, 라이브러리 버전(기록만 남기면 됨), `code/` 안의 구조, 추가로 해 보고 싶은 실험. 다만 위 "반드시 같은 것" 표에 있는 값을 바꾸면 두 모델 비교가 깨지므로, 바꿔야 하면 먼저 이슈를 열고 상대 팀 동의 뒤 `settings.py` 버전을 올린다.

## 공식 실행 전에 세 가지만 확인

1. 공격 코드가 모델에 넣는 pixel_values = 프로세서가 같은 사진으로 만드는 값 (차이 0)
2. 양자화한 층 수가 의도와 같다 (`quant_rtn.census`)
3. 같은 사진을 두 번 넣으면 같은 답
