# 공통 규칙 — 두 팀이 똑같이 지킬 것

이 폴더에 있는 것:

| 파일 | 내용 |
|---|---|
| `README.md` (이 문서) | 규칙 한 장 |
| `settings.py` | 고정값. 코드에서 import해서 쓴다 |
| `quant_rtn.py` | 가짜 양자화와 확인(census) 함수. 두 팀이 같은 것을 쓴다 |
| `실험설계.md` | 무엇을 왜 재는가, 1차·2차 실험, 가설 |
| `진행단계.md` | 0~4단계. 각 단계에서 무엇을 만들어 어디에 두는가 |
| `결과형식.md` | 결과 CSV 열, 지표 정의 |
| `일정.md` | 10/30까지 주차별 계획, 역할, 안 될 때 대응 |
| `image_list.csv` | 두 팀 공통 사진 목록 |

## 1. 고정값은 `settings.py` 한 곳에만

실험 조건은 전부 `settings.py`에 있고 버전 번호(`SETTINGS_VERSION`)가 붙어 있다. 결과 CSV마다 이 버전이 기록되고, 버전이 다른 결과는 한 표에 넣지 않는다.

바꾸고 싶으면: 이슈를 열어 무엇을 왜 바꾸는지 적는다 → 상대 팀 1명 이상 동의 → `settings.py` 값과 버전을 올리고 이 문서의 표도 고쳐서 PR 하나로.

## 2. 두 팀이 똑같이 하는 것

| 항목 | 값 | 왜 |
|---|---|---|
| 질문 | "Describe this image in one sentence." | 평소 답이 짧아야 공격 효과가 보인다 |
| 답 생성 | greedy, beam 1, repetition_penalty 1.0, 샘플링 끔 (`settings.GEN_KWARGS`를 그대로 넘김) | 같은 입력이면 같은 답. 모델 기본값(Qwen은 샘플링 켜짐)에 기대지 않는다 |
| 답 상한 | 512 토큰 | 512 = 스스로 못 멈춤 |
| 종료 토큰 | 모델 generation_config의 eos_token_id **전부** | Qwen은 2개다 |
| 노이즈 상한 ε | 8/255 | "사람 눈에 안 보임"의 기준. 바꾸지 않는다 |
| 사진 크기 | SmolVLM 512×512(조각내기 끔), Qwen2-VL 448×448 | 모델 입력 크기로 바로 맞춰야 프로세서가 사진을 다시 건드리지 않는다 |
| 리사이즈 | 자르지 않고 정사각형으로, BICUBIC | 두 팀이 같은 내용을 본다 |
| 저장 | 무손실 PNG | JPEG는 노이즈를 지운다 |
| 사진 | `image_list.csv`의 eval 후보 중 유효 30장 (`eval_v1.txt`) | 두 팀 같은 사진 |
| 기준 정밀도 | bf16 (GPU가 bf16을 지원해야 함) | 원본 배포 형식 |
| 양자화 대상 | Linear 층의 weight만 | Conv·LayerNorm·bias·임베딩은 원본 |
| 가짜 양자화 | `quant_rtn.py`의 `apply_rtn` (그룹 64, 균등 반올림) | 각자 짜면 방식이 달라진다. 확인값: SmolVLM 비전 인코더 4비트에서 가중치 변화 9.38% (예비 실험 nf4 9.42%와 같은 크기) |
| 실제 양자화 | bitsandbytes 8(LLM.int8)·4(nf4), CUDA 전용 | 예비 실험과 이어지는 기준점 |
| 노이즈 대조군 | ±8 부호 무작위, 시드 (2026, COCO id). 만드는 법은 `진행단계.md` 1단계 | 공격과 같은 크기의 '방향 없는' 노이즈 |
| 경우 이름 | `ref`, `rtn-V-4`, `bnb-V-8`, `rtn-VCLH-4` 형식 | 두 팀 결과를 한 표로 합치기 위해 |

## 3. 상한선

| 항목 | 상한 | 넘으면 |
|---|---|---|
| 공격 반복 수 | 기본 300, 최대 500 | 500에서 멈추고 그때까지의 최선을 저장 |
| 공격 시간 (사진 1장) | SmolVLM 5분, Qwen2-VL 20분 | 그때까지의 최선을 저장, 로그에 사유 |
| 1차 GPU 시간 | 팀당 10시간 | 사진 수를 줄이지 말고 여유분 경우(`phase1-extra`)부터 뺀다 |
| 사진 수 | 1차 30장, 후보 48장 안에서 | 더 필요하면 사진 목록 v2를 두 팀이 같이 만든다 |
| 비트 | 1차 {8, 6, 5, 4, 3} | 2비트는 여유분 |

## 4. 하지 말 것

1. 평가용(eval) 사진으로 공격 설정을 고치는 것. 조정은 dev 5장으로만.
2. 공격 사진을 고정(해시 기록)한 뒤 다시 만드는 것. 꼭 필요하면 새 세트 이름(`adv_v2`)으로.
3. 결과 CSV를 손으로 고치는 것. 잘못됐으면 다시 돌린다.
4. 설정 버전이 다른 결과를 한 표에 넣는 것.
5. JPEG 저장, 사진 자르기, 질문 바꾸기, 샘플링 켜기.
6. 다른 기계의 시간·에너지를 비교하는 것. 시간은 같은 실행 안에서 ref 대비 비율로만. 주 지표는 토큰 수.
7. 공격 사진을 팀 밖으로 보내거나 우리가 띄우지 않은 서비스에 넣는 것.

## 5. 공식 실험 전에 확인할 것 (0단계)

- [ ] 전처리 일치: 공격 코드가 만드는 pixel_values와 프로세서가 같은 사진으로 만드는 값의 차이 최댓값 = 0
- [ ] census: 모델의 모든 Linear가 V/C/L/H 중 정확히 하나에 속함
- [ ] 종료 토큰 목록과 질문 템플릿 출력 확인
- [ ] 같은 사진 두 번 → 같은 답
- [ ] GPU가 bf16 지원, 메모리, bnb 가능 여부
- [ ] `settings.SETTINGS_VERSION`이 두 팀 같음

결과는 실험기록 이슈에 붙인다. 환경이 바뀌면 다시 한다.

## 6. 실험 하나(run)마다 남길 것

- `<팀>/results/<실행ID>.csv` — 답 하나가 한 줄 (열은 `결과형식.md`)
- `<팀>/results/<실행ID>.json` — 설정 버전·설정 스냅샷·환경(GPU, 패키지 버전, git 커밋)·경우별 census와 가중치 변화·실행 명령·시작·끝 시각
- 실험기록 이슈 1개 (템플릿 있음)
- 실행 ID: `YYYYMMDD-HHMMSS_<모델>_<묶음>` 예) `20261018-213000_smolvlm_phase1`

## 7. 하나만 두는 코드

두 팀이 각자 짜면 규칙이 같아도 숫자가 달라질 수 있는 것은 하나만 둔다.

- 고정값: `공통규칙/settings.py`
- 가짜 양자화·census: `공통규칙/quant_rtn.py`
- 공격 사진 코드: `이미지생성/attack_smolvlm.py` (B팀은 정해진 항목만 바꾼 복사본)
- 4단계 분석(지표·신뢰구간·그림): 공동 담당 1명이 하나만 만들고 두 팀 CSV를 모두 그걸로 계산한다. 팀별로 따로 계산한 숫자는 발표에 쓰지 않는다.
- 3단계 평가 코드는 팀마다 달라도 되지만, 생성 설정·결과 열·census는 그대로 따르고 상대 팀이 PR에서 확인한다.

## 8. Git

- 브랜치 `a/<내용>`, `b/<내용>`, `공통/<내용>`. `main`에 직접 커밋하지 않는다(무료 조직이라 강제 보호가 안 되니 규칙으로 지킨다).
- 커밋 메시지 `[A] 공격 사진 30장 생성 로그` 처럼 팀 표시 + 내용. 결과 커밋에는 실험기록 이슈 번호(`#12`).
- 결과 PR은 **상대 팀** 1명이 체크리스트를 보고 승인한다.
- 커밋하는 것: 코드, 문서, 사진 세트 PNG(세트당 수십 MB), 결과 CSV·JSON, 그림. 커밋하지 않는 것: COCO 원본 캐시, 모델 가중치, 가상환경(`.gitignore`).
- 노트북은 결과 셀을 지우고 올린다.

## 9. 윤리

공개 모델과 공개 데이터(COCO)만, 우리 기기에서만. 보고서에는 결과와 함께 대가(품질·용량)와 한계를 같은 비중으로 적는다.
