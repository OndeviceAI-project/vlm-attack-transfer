# 공격 사진 생성

`attack_smolvlm.py`로 만든다(예비 실험 코드에서 프로세서 한 줄과 저장할 사진을 고르는 방식을 고친 것 — 아래 "예비 실험 코드에서 바뀐 것"). A팀은 이 파일을 쓰고, B팀은 복사해서 모델 부분만 고친다.

```
python attack_smolvlm.py --images <원본 PNG 폴더> --out <출력 폴더> --iter 300
```

| 인자 | 값 | |
|---|---|---|
| `--images`, `--out` | 입력·출력 폴더 | 자유 |
| `--iter` | 300 (최대 500) | 두 팀 같게 |
| `--eps` | 8 | 바꾸지 않음 |
| `--step` `--target_len` `--refresh` `--w_unc` `--w_div` | 1 / 128 / 20 / 0.05 / 0 (`settings`와 같음) | 두 팀 같게 |
| `--overwrite` | 있는 사진을 다시 만듦 | 고정한 뒤에는 쓰지 않음 |

출력 폴더에 같은 이름의 PNG가 있으면 건너뛰므로, 끊겨도 같은 명령으로 이어서 할 수 있다.

## 지킬 것

1. **공격이 보는 사진 = 평가가 보는 사진.** 코드가 모델에 넣는 pixel_values가 프로세서가 같은 PNG로 만드는 값과 같아야 한다(차이 0). SmolVLM은 프로세서에 `size={"longest_edge": 512}`를 준다. 이 스크립트는 그렇게 만든다. 평가 코드처럼 프로세서를 따로 만드는 곳에서도 같은 값을 준다(`settings`의 `processor_kwargs`).
2. **저장본으로 확인.** 저장한 PNG를 원본 PNG와 비교해 최대 차이 ≤ 8인지, 원본 모델에서 답이 길어졌는지 확인한다. 답 길이는 스크립트가 사진마다 출력하는 '저장본 실제 답 길이'를 쓴다(저장하는 PNG와 같은 픽셀로 잰다). 1번 노트북의 확인 셀은 프로세서 크기를 지정하지 않아 다른 사진으로 재므로 쓰지 않는다. 스크립트가 '주의: 저장본 답 길이가 고를 때와 다르다'를 출력한 사진은 따로 확인한다. 8을 넘는 파일이 있으면 그 세트는 쓰지 않는다.
3. **한 번 만들면 고정.** 30장이 끝나면 `shasum -a 256 *.png > SHA256SUMS`. 조정은 dev 5장에서만.
4. **실패한 사진도 남긴다.** 답이 안 길어진 사진도 저장하고 로그에 적는다. 성공률은 30장 전체로.

로그는 사진마다 한 줄이면 된다: `image_id, iters_run, seconds, start_len, best_len, saved_len, linf`(iters_run = 실제로 한 업데이트 수, best_len = 스크립트가 출력한 '고른 사진'의 답 길이, saved_len = 스크립트가 출력한 '저장본 실제 답 길이', linf = 저장본과 원본의 최대 픽셀 차이). B팀 공통 세트의 `attack_log.csv`도 이 열을 쓴다(B팀은 `numerical_failure` 열이 하나 더 있다).

## 예비 실험 코드에서 바뀐 것

두 가지를 바꿨다. 손실, 노이즈를 고치는 계산, 노이즈 상한, 목표 문장 갱신, 20걸음마다 답 길이를 재는 것은 예비 실험 코드 그대로다.

### 1. 프로세서 크기

프로세서를 만드는 한 줄을 바꿨다.

```python
processor = AutoProcessor.from_pretrained(MODEL_ID)                                  # 전
processor = AutoProcessor.from_pretrained(MODEL_ID, size={"longest_edge": 512})      # 후
```

왜 바꿨나:

- **기본 설정의 프로세서는 사진을 바꾼다.** 기본값(`longest_edge` 2048)이면 512×512 사진을 2048로 키웠다가 512로 다시 줄인다. clean 35장(eval 30 + dev 5)으로 재면, 사진을 직접 정규화한 값과 사진마다 최대 6~46/255, 평균 0.06~4.61/255 달랐다. 노이즈 상한이 8/255이므로 노이즈보다 큰 차이다.
- **이 스크립트는 그 바뀐 사진으로 공격이 됐는지를 판단하고 있었다.** 답 길이를 잴 때(진행 출력, 512 도달 조기 종료, 저장본 길이)와 목표 문장을 뽑을 때 프로세서를 거친 사진을 쓴다. 평가가 보는 사진과 다른 사진이므로 '지킬 것' 1번(README '반드시 지킬 것' 5번)에 어긋난다.
- **노이즈를 고치는 계산은 원래 맞았다.** 기울기를 구할 때는 사진을 직접 정규화한 값을 넣는다. 이 부분은 바뀌지 않았다. 바뀐 것은 "얼마나 길어졌나"를 재는 기준 사진뿐이다.
- **고친 뒤에는 같은 35장 모두 차이가 0이다.**

그 아래 줄(`do_image_splitting = False`)은 그대로 둔다.

### 2. 저장할 사진 고르기와 조기 종료

| | 전 | 후 |
|---|---|---|
| 저장할 사진 | 마지막 걸음의 사진 | 답 길이를 잰 시점(원본 포함) 중 가장 높은 사진. ① 종료 토큰 없이 512에 닿았는가 ② 답 길이 순으로 비교하고, 같으면 앞의 것 |
| 답 길이를 재는 때 | 1, 21, 41, …번째 업데이트 뒤 | 같음 + 마지막 업데이트 뒤 |
| 조기 종료 | 답 길이 500 이상이 두 번 연속 | 종료 토큰 없이 512가 두 번 연속 |
| 원본 답이 이미 512 | 공격함 | 공격하지 않고 원본 그대로 저장 |

출력에는 `고른 사진:` 줄과, 종료 토큰 없이 512에 닿은 줄 끝의 `(종료 없이 512)` 표시가 더해졌다.

왜 바꿨나:

- **300번을 다 돌면 마지막 걸음의 사진은 답 길이를 재지 않은 사진이었다.** 마지막으로 재는 때는 281번째 업데이트 뒤이고, 그 뒤 19걸음은 재지 않은 채 저장했다. 그 사이 답이 다시 짧아져도 알 수 없었다. 이제는 잰 사진 중에서만 고르므로 저장본은 고를 때 잰 길이를 낸다(저장 후 다시 재서 다르면 '주의'를 출력한다).
- **조기 종료 기준이 성공의 정의와 달랐다.** 성공은 종료 토큰 없이 512에 닿는 것이다(README '반드시 지킬 것' 8번, 결과 표의 `hit_cap`). 전에는 500~511토큰에서 스스로 끝난 답도 닿은 것으로 쳐서 멈출 수 있었다.
- **B팀 공통 세트와 같은 방식이다.** `B팀/adv/qwen2vl_attack_common_v1_i300_cap512_s01/`은 `B팀/src/attack.py`로 위 '후'의 규칙대로 만들었다. 이 README도 전부터 "답이 가장 길었던 시점을 저장하도록, 두 팀이 같은 방식으로" 바꾸기를 권했다. 저장 규칙이 다르면 두 모델의 결과 차이가 모델 때문인지 규칙 때문인지 가를 수 없다.
- **원본 답이 이미 512이면 공격하지 않는다(B팀 코드와 같음).** 종료 토큰 없이 512에 닿은 원본은 이미 가장 높으므로 어느 걸음도 그보다 높지 않아, 공격해도 원본이 저장된다. 결과는 같고 시간만 든다.

공식 실험에 쓸 공격 사진은 두 수정이 모두 들어간 스크립트로 만든다.

## 지금 코드에서 알아둘 것

- 사진 한 장 시간 상한과 로그 파일 쓰기는 없다. 필요하면 넣는다.
- 고정값이 파일 안에 상수로 있다. `공통/settings.py`에서 읽게 바꾸면 틀릴 일이 없다.

## B팀이 바꿀 곳

이대로 고치면 전처리 일치 검사를 통과한다(transformers 5.19에서 확인). 자세한 것은 `참고/Qwen2-VL_메모.md`.

| 곳 | SmolVLM | Qwen2-VL-2B |
|---|---|---|
| `MODEL_ID`, `IMG_SIZE` | SmolVLM-256M-Instruct, 512 | Qwen/Qwen2-VL-2B-Instruct, 448 |
| 프로세서 생성 | `do_image_splitting=False, size={"longest_edge": 512}` | `min_pixels=max_pixels=448*448` |
| 모델 dtype | float32 | bfloat16 |
| `mean`, `std` | 0.5 / 0.5 | 프로세서의 `image_mean`, `image_std` |
| `make_pixel_values()` | `(1, 1, 3, 512, 512)` | 조각 배열 `(1024, 1176)` — 순서는 메모 참고 |
| `losses()`에 넘기는 입력 | `pixel_attention_mask` | `image_grid_thw` |
| `eos_token_ids()` | 1개 | generation_config의 2개 모두 |
| `build_prompt()` | 그대로 | 그대로 (시스템 문장이 자동으로 붙음) |
