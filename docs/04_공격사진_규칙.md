# 04. 공격 사진 단계의 규칙

이 문서는 **규칙만** 적는다. 코드는 A팀 예비 실험에서 꺼낸 `notebooks/A_smolvlm/attack_smolvlm.py`가 유일한 구현이고(사용법과 수정 목록은 그 폴더의 README), B팀은 그 파일을 docs/07의 항목만 바꿔서 쓴다. 두 팀이 서로 다른 구현을 쓰면 결과 차이가 모델 때문인지 코드 때문인지 알 수 없게 된다.

## 1. 입력과 출력

- 입력: `data/sets/<모델>/clean/` 중 `data/eval_v1.txt`에 있는 30장. 다른 사진(dev)은 설정 확인용으로만.
- 만드는 모델: **원본**(양자화 없음). SmolVLM은 fp32, Qwen2-VL은 bf16(`settings.MODEL_SPECIFIC[...]["attack_dtype"]`). 2차의 적응 공격만 예외로, 양자화한 모델로 만들고 세트 이름을 `adv_on_<경우>`로 둔다.
- 출력: `adv/<id>.png`(무손실 PNG, 원본과 같은 크기), `adv/attack_log.csv`, `adv/SHA256SUMS`.

## 2. 고정값 (settings.py와 같아야 한다)

| 값 | v1 | 비고 |
|---|---|---|
| ε (L∞) | 8/255 | 바꾸지 않는다 |
| 걸음 크기 | 1/255 | |
| 반복 수 | 기본 300, 최대 500 | 1번 노트북 `--iter` |
| 시간 상한 | SmolVLM 5분 / Qwen2-VL 20분 (사진 1장) | 넘으면 그때까지의 최선을 저장하고 로그에 사유 기록 |
| 확인 주기 | 20걸음마다 실제 답 길이 기록 | `--refresh` |
| 목표 답 길이 | 128 | `--target_len` |
| 손실 가중치 | `--w_unc 0.05`, `--w_div 0` | 예비 실험과 같음 |
| 조기 종료 | 실제 답이 상한(512)에 연속 2회 닿으면 | |
| 질문 | 공통 질문 하나 | 평가와 같은 질문으로 만든다 |

## 3. 반드시 지킬 것

1. **공격 경로 = 평가 경로.** 공격 코드가 모델에 넣는 pixel_values는 프로세서가 같은 PNG로 만드는 값과 숫자까지 같아야 한다(0단계 '전처리 일치' 차이 0). 다르면 공격은 평가가 보는 것과 다른 사진을 보고 만든 셈이 된다.
2. **저장본으로 다시 확인한다.** 메모리 속 실수 값이 아니라, PNG로 저장했다가 다시 읽은 사진으로 (a) 원본과의 최대 차이 ≤ 8, (b) 원본 모델에서의 답 길이를 잰다. 이 두 값을 로그에 쓴다. 차이가 8을 넘는 파일이 하나라도 있으면 세트 전체를 공식 결과로 쓰지 않는다.
3. **"가장 길었던 노이즈"를 저장한다.** 마지막 걸음이 아니라 확인 주기마다 잰 답 길이가 가장 길었던 시점의 사진을 저장한다. 현재 `attack_smolvlm.py`는 마지막 걸음을 저장하므로, 공식 실행 전에 A팀이 고치고(그 폴더 README의 TODO 3) B팀은 고친 뒤의 파일을 복사한다.
4. **한 번 만들면 고정.** 30장이 끝나면 해시를 기록하고 PR로 올린다. 이후 이 폴더의 파일을 바꾸지 않는다. 다시 만들어야 하면 `adv_v2`처럼 새 세트로 만들고 이전 결과와 섞지 않는다.
5. **eval 사진으로 설정을 만지지 않는다.** 반복 수·가중치를 바꿔 보는 것은 dev 5장에서만. eval 30장에는 확정된 설정으로 한 번 돌린다.
6. **실패한 사진도 남긴다.** 상한 시간·반복 안에 답이 안 길어진 사진도 저장하고 로그에 `best_len`을 쓴다. 성공한 사진만 골라 쓰면 성공률이 부풀려진다. 성공률(H1)은 30장 전체로 계산한다.
7. **공격 사진은 우리 기기에서만.** 외부 서비스·앱·다른 사람 기기에 넣지 않는다. 저장소는 팀 내부용이다.

## 4. 로그 (사진 한 장 = 한 줄)

`image_id, attack_case(ref 또는 경우 이름), attack_dtype, settings_version, eps, iters_limit, iters_run, minutes, start_len, best_len, saved_len, linf, stop_reason, history, device, time`

- `start_len` 공격 전 답 길이, `best_len` 반복 중 최고, `saved_len` 저장본을 다시 읽어 잰 길이, `linf` 저장본과 원본의 최대 픽셀 차이, `history` "20:45 40:512 ..." 형식의 (걸음:길이) 기록, `stop_reason` 조기 종료 / 반복 수 다 씀 / 시간 상한 / nan 중 하나.

## 5. 성립 기준 (H1)

원본 모델에서 저장본의 답이 상한에 닿은 사진이 30장 중 **24장(80%) 이상**이어야 다음 단계로 간다. 미달이면 dev 사진으로 반복 수(≤500)만 조정해 보고, 그래도 안 되면 그 성공률 그대로 보고하고 전이는 성공한 사진에 대해서만 계산한다(지표 TR의 정의, docs/05).

## 6. B팀이 바꿔도 되는 것 / 안 되는 것

- 바꿔도 되는 것: 모델 이름, 사진 크기(448), pixel_values를 만드는 전처리 식(Qwen 방식), 종료 토큰 목록, 계산 정밀도(bf16), 메모리 절약 옵션(use_cache 끄기 등 결과에 영향 없는 것).
- 바꾸면 안 되는 것: ε, 걸음 크기, 반복·시간 상한, 손실 구성과 가중치, 확인 주기, 목표 답 길이, 질문, 저장 형식, 로그 열.
- 바꾼 항목은 `notebooks/B_qwen2vl/README.md`에 한 줄씩 적는다.
