# Qwen2-VL 시각 인코더 양자화 — 확장 설정 v1 (r01)

[B팀 안내로 돌아가기](../../README.md)

## 1. 실험 목적과 변경점

공격 갱신을 500회까지 수행하고 출력 상한을 5,000토큰으로 늘려 측정했다. 출력이 긴 후보를 한 번 더 확인해 채택하는 절차를 추가한 확장 실험이다.

원본 bf16 모델에서 만든 공격 PNG를 고정하고, 같은 사진의 원본(clean)·무작위 노이즈(noise)·공격(adv) 입력을 원본과 시각 인코더 양자화 모델에서 비교했다. **성공·실패, ASR, 전이율은 아직 평가하지 않았다.**

프로젝트 공동 설정의 출력 상한 512토큰과 다른 **별도 확장 실험**이다. 공통 설정 결과와 하나의 조건으로 합산하지 않는다. 재검사에서 비슷한 토큰 수가 나오는지를 확인하는 것은 이미지 채택 절차이며 공격 성공 판정이 아니다.

## 2. 설정과 이미지 채택 규칙

| 항목 | 적용한 값·규칙 |
|---|---|
| 실험 ID | `qwen2vl_vision_extended_v1_r01` |
| 이미지 세트 ID | `qwen2vl_attack_extended_v1_i500_cap5000_tol20_s01` |
| 원본 모델 | `Qwen/Qwen2-VL-2B-Instruct`, bf16 |
| 측정 대상 | 시각 인코더(V)의 Linear weight만 양자화 |
| 모델 조건 | `ref`, `rtn-V-8`, `rtn-V-6`, `rtn-V-5`, `rtn-V-4`, `rtn-V-3`, `bnb-V-8`, `bnb-V-4` |
| 사진·입력 | COCO val2017 eval 30장 × clean·noise·adv. dev 5장은 점검용 |
| 전처리 | RGB 448×448 직접 BICUBIC 리사이즈, 무손실 PNG |
| 노이즈 대조군 | seed `[2026, image_id]`, 각 채널에 ±8을 더한 뒤 0…255로 제한 |
| 공격 변화 제한·갱신 크기 | 채널당 최대 8, 즉 `8/255`; 한 번의 갱신 크기 `1/255` |
| 기타 공격 설정 | target 128, refresh 20, `w_unc=0.05`, `w_div=0` |
| 질문·생성 | `Describe this image in one sentence.`, greedy |
| 최대 출력 | 5,000토큰 |
| 공격 갱신 예산 | 500회 모두 수행 |
| 후보 출력 확인 | 갱신 20, 40, …, 500회, 사진당 총 25회 |
| 조기 종료 | 긴 답변이 나오더라도 500회 전에는 종료하지 않음 |
| 후보 순서 | 최초 출력 토큰 수가 많은 순서. 동률이면 이른 갱신 위치 우선 |
| 재검사·채택 | 위 순서로 한 후보씩 다시 생성해, 최초 대비 상대 오차가 20% 이하인 첫 후보 채택 |
| 저장 확인 | 재검사 입력과 최종 PNG의 SHA-256 일치 확인 |
| CSV 형식 | EOS 종료 여부와 출력 제한 도달 여부를 나눈 9열 |
| 평가 행 수 | 30장 × 8모델 조건 × 3입력 = 720행 |

상대 오차는 `abs(재검사 토큰 수 − 최초 토큰 수) / 최초 토큰 수`다. 예를 들어 5,000→4,000은 20%로 채택 가능하고, 5,000→3,999는 범위를 벗어난다.

대표 CSV는 `model,case,image_id,input,n_tokens,ended_eos,output_limit_reached,latency_s,text` 순서다. 두 상태를 분리해 기록한 확장 형식이다.

[후보 측정 요약](../../results/qwen2vl_vision_extended_v1_r01/candidate-measurements.json)에는 30장 × 25회 = 750개 후보의 반복 위치·토큰 수·해시·픽셀 변화가 있다. [상세 응답](../../results/qwen2vl_vision_extended_v1_r01/responses.jsonl)에는 최종 평가 720행의 답변·토큰 ID·전처리 검사 기록이 있다. 후보별 전체 답변이나 중간 PNG 전체를 포함하는 것은 아니다.

채택 PNG와 사진별 정보는 [이미지 세트](../../adv/qwen2vl_attack_extended_v1_i500_cap5000_tol20_s01/)의 `selection.json`·`SHA256SUMS`에 있다. 모든 모델 조건에 같은 PNG를 사용했다. 최종 PNG의 최대 픽셀 변화와 공격 경로·평가 프로세서의 전처리 일치 여부를 검사했다.

토큰 수는 생성된 EOS가 있으면 그 토큰도 포함한다. Qwen EOS ID `151645`, `151643`을 모두 확인했다. 토큰 수가 상한과 같아도 마지막에 EOS가 있으면 출력 제한 도달로 세지 않는다.

`latency_s`는 CUDA 동기화를 포함한 생성 호출 시간이다. 모델 로딩과 공격 이미지 최적화 시간은 제외한다. RTN은 group 64의 양자화 값을 부동소수점 가중치로 되돌려 쓰는 모의 양자화이며, bnb는 실제 8비트·4비트 모듈을 사용한다. 4비트 형식은 NF4다.

아래 표는 출력 길이·생성 시간의 기술 통계다. 출력 상한 도달 장수를 공격 성공 수로 단정하거나, 이 표만으로 답변 정확도·메모리 절감·토큰당 속도의 우열을 판단하지 않는다.
