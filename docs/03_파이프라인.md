# 03. 파이프라인 — 0단계부터 5단계까지

```
 data/image_list.csv ──┐
                       ▼
 [1] 사진 준비 ──► clean/*.png ──► noise/*.png
                       │
                       ▼ (원본 모델, 1회, 고정)
 [2] 공격 사진 ──► adv/*.png + attack_log.csv + SHA256SUMS
                       │
                       ▼ (경우마다 모델을 올려 같은 PNG를 넣는다)
 [3] 전이 실험 ──► results/<모델>/<실행ID>.csv + .json
                       │
                       ▼ (두 팀 결과를 합친다)
 [4] 분석 ──► reports/phase1/summary.csv, summary.md, 그림
                       │
                       ▼ (최종 보고서용)
 [5] 원인 분석 ──► results/<모델>/cause_*.csv
```

코드는 팀별 노트북 폴더에 있다. A팀은 예비 실험 노트북 1~6을 그대로 이어 쓰고(단계 대응표는 `notebooks/A_smolvlm/README.md`), B팀은 docs/07에 따라 고친다. 아래는 각 단계에서 **무엇이 들어가고 무엇이 나와야 하는지**다. 코드 모양은 달라도 입력·출력·파일 이름은 같아야 한다.

## 0단계. 환경 점검

- 입력: 없음. 출력: docs/02 E 체크리스트 결과(실험기록 이슈에 붙임).
- 공식 실험 전에 한 번. 특히 **전처리 일치(차이 0)**와 **census**가 통과해야 다음 단계로 간다.

## 1단계. 사진 준비 + 유효성 검사

- 입력: `data/image_list.csv`(split=eval 후보 43장, dev 5장).
- 할 일: COCO 원본을 내려받아(`data/coco_cache/`, 커밋 안 함) 모델 크기 정사각형으로 리사이즈(자르지 않음, BICUBIC) → `data/sets/<모델>/clean/<12자리 id>.png`. 같은 사진에 노이즈 대조군 → `noise/<id>.png`.
- **노이즈 대조군 만드는 법(두 팀 동일)**: clean PNG를 `int16` 배열로 읽고, `numpy.random.default_rng([2026, coco_id])`로 픽셀·채널마다 −1 또는 +1을 뽑아(`rng.choice([-1, 1], size=arr.shape)`) `arr + 8 * sign`을 0~255로 잘라 `uint8`로 저장한다. 같은 id면 어느 기계에서든 같은 파일이 나온다. 저장 뒤 원본과의 최대 차이가 8인지 확인한다.
- **유효성 검사**: 3단계 코드를 경우 `ref`, 입력 `clean`만으로 eval 후보 43장에 돌려, 답이 상한(512)에 닿는 사진을 골라낸다. **A팀 검사에서 통과한 id 중 order가 빠른 30장**을 `data/eval_v1.txt`(한 줄에 id 하나)로 확정한다. B팀 검사가 10/14까지 준비되면 두 모델 모두 통과한 id로 확정하고, 준비되지 않으면 A팀 검사만으로 확정한다 — B팀에서 자연 반복이 나오는 사진은 docs/05의 '유효 사진' 정의에 따라 B팀 결과에서만 빠지므로 목록을 다시 만들 필요가 없다. 이 확정이 **2단계보다 먼저**여야 한다.
- 출력: clean 48장, noise 48장(PNG), `data/eval_v1.txt`.
- 시간: 수 분.

## 2단계. 공격 사진 (규칙은 docs/04)

- 입력: `clean/` 중 eval_v1 30장, 원본 모델(SmolVLM fp32 / Qwen2-VL bf16).
- 출력: `data/sets/<모델>/adv/<id>.png` 30장, `adv/attack_log.csv`(사진마다 한 줄, 열은 docs/05 §3), `adv/SHA256SUMS`.
- 고정 절차: 30장이 다 만들어지면 `shasum -a 256 *.png > SHA256SUMS`를 만들고 PNG·로그·해시를 한 PR로 올린다. 이후 이 폴더는 바꾸지 않는다.
- 시간: SmolVLM 약 1시간, Qwen2-VL 밤새(사진당 상한 20분).

## 3단계. 전이 실험

- 입력: 경우 목록(`settings.PRESETS`), eval_v1 30장 × {clean, noise, adv}.
- 가짜 양자화(rtn)는 `common/quant_rtn.py`의 `apply_rtn`을, 확인은 같은 파일의 `census`·`check_census`를 두 팀이 그대로 쓴다. bnb 경우는 노트북 2번의 `load_case` 방식(건너뛸 부품을 `llm_int8_skip_modules`에 지정) 그대로.
- 경우마다: 모델 올리기 → census로 의도한 부품만 양자화됐는지 확인(아니면 즉시 중단) → 준비 운동 1회(기록 안 함) → (사진 × 입력) 90개를 **무작위 순서**로 돌리며 답 하나마다 CSV 한 줄 → 모델 내리기.
- 실행 하나에 `ref`가 반드시 들어간다. 중간에 멈추면 그때까지의 CSV는 남기고, 이어서 돌릴 때는 새 실행 ID로 전체를 다시 돌린다(경우 간 조건을 같게 하기 위해).
- 출력: `results/<모델>/<실행ID>.csv`, `.json`(환경·설정 스냅샷·census·가중치 변화·명령·시각).
- 시간: 경우당 SmolVLM 약 5분, Qwen2-VL 약 15분(공격 사진 30장이 512토큰까지 가므로 대부분 여기서 쓴다).

## 4단계. 분석

- 입력: 두 팀의 결과 CSV(설정 버전이 같은 것만).
- 출력: `reports/phase1/summary.csv`(경우 × 지표), `summary.md`(발표용 표), 그림 2·3·4(docs/01 §7). 지표 정의는 docs/05.
- 두 팀 결과를 합칠 때 모델별로 각자의 `ref`를 기준으로 계산한다. 모델 간에는 비율만 비교한다.

## 5단계. 원인 분석 (최종 보고서용, 10/30에는 선택)

- A팀 6번 노트북의 측정 항목(가중치 변화, 그림 정보의 공격 방향 보존·흔들림 비율, 종료 점수 차, 문장 끝 종료 여유)을 1차 경우(V 비트별)와 사진 30장으로 다시 잰다.
- 출력: `results/<모델>/cause_<실행ID>.csv`. B팀은 같은 항목을 Qwen2-VL에서 잴 수 있으면 잰다(연결부 = `model.visual.merger` 출력).

## 파일 이름 규칙

| 것 | 이름 | 예 |
|---|---|---|
| 사진 | COCO id 12자리 + `.png` | `000000000872.png` |
| 세트 폴더 | `clean` / `noise` / `adv` / `adv_on_<경우>`(적응 공격) | `data/sets/qwen2vl/adv_on_rtn-V-4/` |
| 실행 ID | `YYYYMMDD-HHMMSS_<모델>_<묶음>` | `20261018-213000_smolvlm_phase1` |
| 결과 | `results/<모델>/<실행ID>.csv` + `.json` | |
| 보고서 | `reports/<묶음>/summary.csv`, `summary.md`, `fig2_transfer_by_bits.png` 등 | |
