# 07. B팀 가이드 — A팀 코드를 Qwen2-VL-2B에 맞추기

A팀 노트북(SmolVLM)을 복사해 아래 항목만 바꾼다. 바꾼 항목은 `notebooks/B_qwen2vl/README.md`에 한 줄씩 적는다. 두 모델의 차이를 미리 알고 시작하면 하루 안에 0단계 점검을 통과할 수 있다.

## 1. 모델과 사진 크기

| 항목 | SmolVLM-256M (A) | Qwen2-VL-2B (B) |
|---|---|---|
| 모델 이름 | HuggingFaceTB/SmolVLM-256M-Instruct | Qwen/Qwen2-VL-2B-Instruct |
| 사진 크기 | 512×512, 조각내기 끔 | **448×448** (28의 배수여야 함) |
| 프로세서 설정 | `do_image_splitting=False, size={"longest_edge": 512}` | `min_pixels = max_pixels = 448*448` |
| 이미지 토큰 수 | 64 | 256 (14px 조각 1024개를 2×2로 합침) |
| 질문 포함 입력 길이 | 76 토큰 | 284 토큰 (시스템 문장 포함) |
| 정규화 | 평균 0.5, 표준편차 0.5 | CLIP 평균·표준편차 (프로세서 값 사용) |
| 공격 계산 정밀도 | fp32 | **bf16** (2B를 fp32로 역전파하면 메모리가 모자람) |
| 종료 토큰 | 1개 (49279) | **2개** (`<|im_end|>`, `<|endoftext|>`) — generation_config 목록 전부 |
| 채팅 양식 | 질문만 | 기본 시스템 문장 "You are a helpful assistant."가 자동으로 붙음. **그대로 둔다** (지우면 평소 답이 달라짐) |

448을 고른 이유: Qwen2-VL은 사진 크기에 따라 토큰 수가 달라진다. 크기를 못 박지 않으면 사진마다 입력 길이가 달라져 비교가 흐려진다. 448은 28의 배수 중 SmolVLM(512)과 비슷하고 메모리가 감당되는 값이다. 모든 사진을 448×448로 리사이즈한 뒤 min/max_pixels로 프로세서가 다시 줄이지 못하게 한다.

## 2. pixel_values 모양이 다르다

SmolVLM은 `(1, 1, 3, 512, 512)` — 사진 한 장이 그대로 들어간다.
Qwen2-VL은 `(1024, 1176)` — 사진을 14×14 조각으로 잘라 한 줄로 편 것이고, 같은 사진을 **2프레임 영상처럼 복사**해서 넣는다(1176 = 3채널 × 2프레임 × 14 × 14). 모델 입력에 `image_grid_thw = [[1, 32, 32]]`가 함께 들어간다.

공격 코드에서 pixel_values를 직접 만들 때는 transformers의 `Qwen2VLImageProcessor.patchify`가 하는 reshape·permute 순서를 **그대로** 따라야 한다. 0단계 '전처리 일치' 검사(프로세서 결과와의 차이 0)를 통과할 때까지 공식 실행을 시작하지 않는다. 확인된 사실: transformers 5.19에서 448×448 사진을 (정규화 → `reshape(1, 3, 16, 2, 14, 16, 2, 14)` → `permute(0, 2, 5, 3, 6, 1, 4, 7)` → 2프레임 복사 → `reshape(1024, 1176)`)로 만들면 프로세서와 차이가 0이다.

## 3. 부품 이름 (census의 PARTS)

| 글자 | SmolVLM | Qwen2-VL-2B | Linear 수(대략) |
|---|---|---|---|
| V 비전 인코더 | `model.vision_model` | `model.visual.blocks` | 128 (블록 32개 × 4) |
| C 연결부 | `model.connector` | `model.visual.merger` | 2 |
| L 언어모델 | `model.text_model` | `model.language_model` | 196 (층 28개 × 7) |
| H 출력층 | `lm_head` | `lm_head` | 1 |

`model.visual.patch_embed`는 Conv라 양자화 대상이 아니다(SmolVLM도 첫 Conv는 원본 그대로). census에서 "어디에도 안 속하는 Linear"가 나오면 PARTS를 고친다. 숫자는 0단계에서 실제로 세어 README에 적는다.

**주의 — 출력층(H) 경우.** Qwen2-VL-2B는 입력 임베딩과 출력층이 가중치를 공유(tie)하는 것으로 알려져 있다(`config.tie_word_embeddings` 확인). 가짜 양자화를 제자리에서 하면 **입력 임베딩까지 같이 바뀐다**. H 경우를 돌릴 때는 lm_head 가중치를 복사해 끊은 뒤 양자화한다. 1차(V만)에서는 상관없다.

## 4. 메모리와 시간

- 모델 bf16 약 4.4GB. 공격(역전파) 때 활성값까지 더해 16GB GPU에서 돌아갈 것으로 예상하나, 안 되면 (1) `use_cache=False` 확인 (2) 목표 답 길이는 바꾸지 말고 사진 크기를 336(토큰 144)으로 줄이는 것을 **설정 변경 절차(docs/02 G)**로 제안한다.
- 공격 사진 1장: 수 분~20분(상한). 30장은 밤새.
- 평가: 공격 사진은 512토큰까지 가므로 장당 15~25초. 경우당 90개 → 15분 안팎. phase1 8경우 ≈ 2시간.
- bnb 경우(`bnb-V-8/4`)는 CUDA에서만 된다. `llm_int8_skip_modules`에 V가 아닌 세 부품의 이름을 넣는다.

## 5. GPU

bf16이 되는 GPU(RTX 30/40/50, A10, L4, A100 등)가 필요하다. Colab 무료 T4는 bf16 미지원이라 공식 실험에 쓰지 않는다. Colab Pro의 L4(24GB)·A100이면 된다. 어디서 돌렸든 json에 GPU 이름이 자동 기록되게 한다.
