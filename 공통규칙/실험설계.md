# 실험 설계 — 무엇을 왜 재는가

## 질문

공격자는 공개된 **원본 모델**로 공격 사진을 만든다. 피해자 기기에는 **양자화한 모델**이 들어 있다. 두 모델은 거의 같지만 가중치가 조금씩 다르다.

- **주 질문.** 원본 모델로 만든 공격은 몇 비트까지 살아남는가? → 비트 수에 따른 전이율 곡선
- **보조 1.** 공격이 죽는 지점에서 모델은 멀쩡한가, 모델이 망가져서 공격도 같이 죽은 것인가? → 전이율 ↔ 정상 답 품질 ↔ 용량의 trade-off
- **보조 2.** 어느 부품의 양자화가 결과를 정하는가? → 2차
- **보조 3.** 공격이 죽은 것은 진짜 방어인가, 원본에 맞춘 노이즈가 어긋난 것뿐인가? → 2차(적응 공격)

교수님 공지(9/23): 결론은 "수치적으로 얼마나 나아졌는지, 어떤 trade-off가 있었는지"에 집중. 그래서 마지막 그림은 **비트 수 → 전이율·정상 답 품질·용량**을 한 번에 보여 주는 trade-off 그래프다.

## 예비 실험이 알려 준 것 (SmolVLM-256M, 사진 3장)

| 양자화한 부품 | 8비트 | 4비트(nf4) |
|---|---|---|
| 비전 인코더 | 공격 유지 3/3 | **공격 무력화 0/3** |
| 연결부 | 3/3 | 3/3 |
| 언어모델 | 3/3 | 3/3 |
| 출력층 | 3/3 | 3/3 |

네 부품 모두 4비트에서 가중치가 9~11% 바뀌었는데 결과가 갈린 건 비전 인코더뿐이었다. 노이즈가 지나가는 자리를 거칠게 반올림했을 때만 공격이 흐트러진다는 뜻이다. 자세한 수치는 `A팀/참고_예비실험/부분별_양자화_결과분석.pdf`.

예비 실험의 한계가 이번 설계의 출발점이다: 사진 3장 → 30장. 8과 4 사이가 비어 있음 → 8·6·5·4·3. 4비트 방식이 하나 → 비트 스윕은 한 방식(rtn)으로 통일. 정상 답 품질을 안 쟀음 → 같이 잰다. 진짜 방어인지 모름 → 2차 적응 공격. 모델 하나 → 두 모델.

## 왜 이렇게 하는가 (설계 원칙)

1. **부품은 비전 인코더로 고정, 비트만 바꾼다.** 예비 실험에서 결과가 갈린 유일한 부품이라 8과 4 사이 어딘가에 문턱이 있을 것이다. 다른 부품은 평평한 선이 나올 가능성이 높아 2차에서 확인만 한다. 비전 인코더는 SmolVLM에서 약 93M, Qwen2-VL-2B에서 약 675M 파라미터라 용량 비중도 크다.
2. **비트 스윕은 한 가지 방식으로.** bitsandbytes는 8·4비트만 되므로, 그룹 64 균등 반올림(rtn)으로 8·6·5·4·3을 만든다(`quant_rtn.py`). bnb 8·4는 예비 실험과 이어지는 기준점으로 같이 돌린다. `rtn-V-4`와 `bnb-V-4`가 비슷하면 "방식과 무관하게 비트가 결정한다"는 근거가 된다.
3. **사진 30장, 두 모델 같은 목록.** 30장이면 비율의 95% 신뢰구간이 ±15%p 안쪽이라 "90%에서 30%로 떨어졌다"를 분명히 말할 수 있다.
4. **대조군 두 개.** (a) 무작위 노이즈: 같은 크기(±8)의 노이즈를 방향만 무작위로. 효과가 "노이즈가 있어서"가 아니라 "계산된 방향이라서"임을 보인다. (b) 원본 사진의 답: 양자화 모델은 공격 없이도 끝없이 말하기도 한다(예비 측정에서 3비트 36%). 이것을 공격 성공으로 세지 않도록 성공의 정의에 넣는다(`결과형식.md`).
5. **성공·유효 사진·지표를 실험 전에 정한다.** 결과를 본 뒤 바꾸지 않는다.
6. **공격 사진은 원본 모델로 한 번만 만들고 고정.** 조정은 dev 5장으로만.
7. **비싼 단계는 공격 생성뿐.** 그 뒤 경우 하나를 더 보는 건 답 생성 90번이면 끝이라 싸다. 여유분(전체 양자화 8/4, 2비트)은 시간이 남으면 거의 공짜로 추가한다.

## 1차 실험 (10/30 발표 대상)

| 구분 | 항목 | 값 |
|---|---|---|
| 바꾸는 것 | 비전 인코더 비트 | 16(ref) / 8 / 6 / 5 / 4 / 3 (rtn) + 8 / 4 (bnb) |
| | 입력 | 원본(clean) / 무작위 노이즈(noise) / 공격(adv) |
| | 모델 | SmolVLM-256M (A) / Qwen2-VL-2B (B) |
| 재는 것 | 답 토큰 수, 상한 도달 | 주 지표 |
| | 시간, 에너지(되는 GPU만) | 보조 |
| | 정상 답 일치(ROUGE-L), 정상 답 상한 도달률 | 품질 |
| 고정 | 질문, 생성 설정, ε, 사진, 크기, bf16, 그룹 64 | `settings.py` v1 |

경우 목록은 `settings.PRESETS["phase1"]`(필수 8개)와 `["phase1-extra"]`(여유분). 예상 시간: 공격 생성 SmolVLM 약 1시간 / Qwen2-VL 4~6시간(밤새), 평가 경우당 SmolVLM 5분 / Qwen2-VL 15분 안팎.

## 2차 실험 (11월, 우선순위 순)

1. **적응 공격.** 공격이 죽은 첫 비트(예: `rtn-V-4`)의 양자화 모델로 공격 사진을 새로 만들어 같은 모델에 넣는다(15장). 통하면 "양자화는 방어가 아니라 노이즈가 어긋난 것", 안 통하면 "양자화가 공격을 어렵게 만든다". 어느 쪽이든 결론이 된다.
2. **부품별 × 비트.** `PRESETS["phase2"]`. 공격 사진은 1차 것 그대로, 평가만. 히트맵.
3. **실제 배포 형식.** A팀은 mlx-community 8/4비트 모델, B팀은 `bnb-VCLH-8/4`로 같은 공격 사진. 가짜 양자화 결과가 실제 압축 모델에서도 같은지.
4. **정상 답 절대 품질.** COCO 사람 캡션 대비 CIDEr/BLEU.

시간이 모자라면 4 → 3 → 2 순으로 뺀다. 1은 끝까지 지킨다.

## 가설과 결과별 해석 (미리 적어 둔다)

| | 가설 | 맞으면 | 틀리면 |
|---|---|---|---|
| H1 | 원본 모델에서 공격 성공률 ≥ 80%, 노이즈 대조군 ≤ 10% | 공격 성립 | dev 사진으로 반복 수만 조정. 노이즈도 길어지면 사진·질문 재검토 |
| H2 | 비트가 낮을수록 전이율 하락. 8비트 ≥ 90%, 문턱은 5~4 사이 | "8비트 배포는 원본과 같은 위험" | 3비트까지 유지되면 "양자화는 보호가 안 된다"(강한 결론). 8비트에서 이미 떨어지면 전처리부터 의심 |
| H3 | 전이율이 떨어지는 비트에서 정상 답 일치도 떨어진다 | "공짜 방어는 없다" | 일치는 유지되고 전이율만 떨어지면 실질적 방어 → 적응 공격으로 확인 |
| H4 | 비전 인코더가 큰 Qwen2-VL이 같은 비트에서 전이율이 더 높다 | "작은 모델이 더 민감" | 반대도 보고. 모델 둘로 일반화하지 않는다 |
| H5 | (2차) 적응 공격은 4비트에서도 통한다 | "양자화는 방어가 아니다" | 공격 비용 증가를 반복 수·시간으로 수치화 |

발표 마지막 문장 틀: "**비전 인코더를 N비트로 줄이면 용량은 A→B MB, 원본 공격의 전이율은 X%→Y%, 정상 답 일치는 P→Q.** 따라서 ___."

## 그림

| 번호 | 그림 | 시점 |
|---|---|---|
| 1 | 원본 / 노이즈 / 공격 사진 + 각각의 답 | 1차 |
| 2 | 비트 수 → 전이율 (두 모델, 95% 신뢰구간) — **핵심** | 1차 |
| 3 | 비트 수 → 정상 답 일치, 양자화 부품 용량 | 1차 |
| 4 | 사진별 답 길이 점 그림 | 1차 |
| 5 | 부품 × 비트 전이율 히트맵 | 2차 |
| 6 | 원본 공격 vs 적응 공격 | 2차 |

## 선행연구에서의 자리

Verbose Images(Gao et al., ICLR 2024)는 큰 VLM의 원본 모델에서 공격을 보였고 압축 모델로의 전이는 다루지 않았다. 우리는 (1) 압축 모델로의 전이를 비트별로 재고, (2) 어느 부품이 전이를 끊는지 밝히고, (3) 그 대가를 같이 보인다.
