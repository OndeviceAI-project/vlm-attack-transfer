## dev 5장 확인 (go/no-go, 10/15까지)

dev 5장으로 공격 사진을 만들어 원본 bf16 Qwen2-VL-2B에서 **3장 이상**이 512에 닿으면 go. 2장 이하면 10/16 회의에서 결정: 반복 수 500까지 → 모델 교체 검토 → "2B에서는 같은 예산으로 성립하지 않았다"도 결과로 쓸 수 있다.

## 참고 — 미리 확인해 둔 것

규칙이 아니라 시간을 아끼라고 적어 둔 것이다. 다른 방법으로 해도 0단계 확인(전처리 일치 0, census, 재현성)만 통과하면 된다.

**사진과 토큰.** 448×448(28의 배수)로 못 박으면(`min_pixels=max_pixels=448*448`) 14px 조각 1024개 → 이미지 토큰 256개, 입력 284토큰. `image_grid_thw = [[1, 32, 32]]`. 사진 크기를 고정하지 않으면 사진마다 토큰 수가 달라진다.

**pixel_values 모양.** `(1024, 1176)`. 사진을 조각으로 잘라 한 줄로 편 것이고, 같은 사진을 2프레임처럼 복사한다(1176 = 3 × 2 × 14 × 14). 직접 만들 때 transformers 5.19 기준 순서: 정규화(CLIP 평균·표준편차) → `reshape(1, 3, 16, 2, 14, 16, 2, 14)` → `permute(0, 2, 5, 3, 6, 1, 4, 7)` → 2프레임 복사 → `reshape(1024, 1176)`. 이렇게 하면 프로세서 결과와 차이 0.

**종료 토큰 2개.** `<|im_end|>`, `<|endoftext|>`. 하나만 보면 끝난 답을 안 끝난 것으로 센다.

**채팅 양식.** "You are a helpful assistant." 시스템 문장이 자동으로 붙는다. 그대로 둔다.

**부품 이름** (`settings.MODEL_SPECIFIC["qwen2vl"]["parts"]`): V `model.visual.blocks`(Linear 약 128), C `model.visual.merger`(2), L `model.language_model`(약 196), H `lm_head`(1). 숫자는 census로 확인. 2B는 입력 임베딩과 출력층이 가중치를 공유할 수 있는데(`tie_word_embeddings`), `apply_rtn`은 새 Parameter로 갈아 끼우므로 1차(V만)에서는 신경 쓸 것 없다.

**메모리·시간.** 모델 bf16 4.4GB. 공격 생성은 16GB GPU에서 될 것으로 보이고, 안 되면 사진 336으로 줄이는 것을 이슈로 제안. 공격 사진 1장 수 분~20분, 30장은 밤새. 평가는 경우당 15분 안팎. bf16이 되는 GPU 필요(Colab 무료 T4는 안 됨).
