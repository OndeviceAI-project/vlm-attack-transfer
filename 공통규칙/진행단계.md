# 진행 단계 — 0단계부터 4단계까지

```
공통규칙/image_list.csv
   ↓
[1] 사진 준비 → <팀>/data/clean/*.png, noise/*.png, 공통규칙/eval_v1.txt
   ↓ (원본 모델로 한 번만, 고정)
[2] 공격 사진 → <팀>/data/adv/*.png + attack_log.csv + SHA256SUMS      (코드: 이미지생성/)
   ↓ (경우마다 모델을 올려 같은 PNG를 넣는다)
[3] 전이 실험 → <팀>/results/<실행ID>.csv + .json
   ↓ (두 팀 결과를 합친다)
[4] 분석 → 발표용 표와 그림
```

코드는 팀 폴더(`A팀/code/`, `B팀/code/`)에 둔다. 코드 모양은 팀마다 달라도 되지만 **각 단계의 입력·출력·파일 이름은 같아야** 한다.

## 0단계. 환경 점검

공통규칙/README.md 5절 체크리스트. 특히 **전처리 일치(차이 0)**와 **census**가 통과해야 다음으로 간다. 결과는 실험기록 이슈에 붙인다.

## 1단계. 사진 준비 + 유효성 검사

- `image_list.csv`의 eval 후보 43장과 dev 5장을 COCO에서 내려받아(`<팀>/data/coco_cache/`, 커밋 안 함) 모델 크기 정사각형으로 리사이즈(자르지 않음, BICUBIC) → `<팀>/data/clean/<12자리 id>.png`.
- **노이즈 대조군**(두 팀 동일): clean PNG를 `int16` 배열로 읽고, `numpy.random.default_rng([2026, coco_id])`로 픽셀·채널마다 −1 또는 +1을 뽑아(`rng.choice([-1, 1], size=arr.shape)`) `arr + 8 * sign`을 0~255로 잘라 `uint8`로 → `noise/<id>.png`. 저장 뒤 원본과의 최대 차이가 8인지 확인.
- **유효성 검사**: 3단계 코드를 경우 `ref`, 입력 `clean`만으로 43장에 돌려 답이 상한(512)에 닿는 사진을 골라낸다. **A팀 검사를 통과한 id 중 order가 빠른 30장**을 `공통규칙/eval_v1.txt`(한 줄에 id 하나)로 확정한다. B팀 검사가 10/14까지 되면 두 모델 모두 통과한 id로, 안 되면 A팀 검사만으로 확정한다. B팀에서 자연 반복이 나오는 사진은 '유효 사진' 정의에 따라 B팀 결과에서만 빠지므로 목록을 다시 만들 필요가 없다.
- 이 확정이 **2단계보다 먼저**여야 한다.

## 2단계. 공격 사진

규칙과 사용법은 `이미지생성/README.md`. 출력은 `<팀>/data/adv/<id>.png` 30장 + `attack_log.csv` + `SHA256SUMS`. 다 만들면 PNG·로그·해시를 한 PR로 올리고, 그 뒤 이 폴더는 바꾸지 않는다.

## 3단계. 전이 실험

- 경우 목록은 `settings.PRESETS`. 실행 하나에 `ref`를 반드시 넣는다(다른 실행의 ref를 빌려 쓰지 않는다).
- 경우마다: 모델 올리기 → rtn이면 `quant_rtn.apply_rtn`, bnb면 건너뛸 부품을 `llm_int8_skip_modules`에 지정 → `census`·`check_census`로 의도한 부품만 양자화됐는지 확인(아니면 즉시 중단) → 준비 운동 1회(기록 안 함) → (사진 30 × 입력 3) 90개를 **무작위 순서**로 돌리며 답 하나마다 CSV 한 줄 → 모델 내리기.
- 답 생성은 `settings.GEN_KWARGS`를 그대로 넘긴다. 결과 열은 `결과형식.md` 1절.
- 중간에 멈추면 그때까지의 CSV는 남기고, 다시 할 때는 새 실행 ID로 전체를 돌린다.
- 출력: `<팀>/results/<실행ID>.csv`, `.json`.

## 4단계. 분석

- 공동 담당 1명이 분석 코드 하나를 만들어(`A팀/code/` 또는 별도 `분석/`) 두 팀의 CSV를 모두 그걸로 계산한다. 지표 정의는 `결과형식.md` 2절, 그림은 `실험설계.md`의 1~4번.
- 모델별로 각자의 `ref`를 기준으로 계산하고, 모델 간에는 비율만 비교한다.
